# Configuration and diagnostics

- CLI defaults: headless `127.0.0.1:8788`, no browser and no initial runtime. `--port 0` requests an ephemeral port. Use `/health` for readiness and `/ws` for SDK v2 initialization.
- Explicit flags: `--host`, `--port`, `--project`, `--static-directory`, `--pid-file`, `--log-directory`, `--no-restart`. Relative paths resolve from invocation cwd. Do not expose the unauthenticated host publicly; a trusted proxy owns auth/TLS. Native connections without Origin are allowed; browser Origin validation remains enabled.
- Runtime settings, credentials, registered packages/extensions and sessions stay under `~/.pi/agent` (Pi's `PI_CODING_AGENT_DIR` can isolate test/runtime state). `PI_CHAT_*` launcher settings are not interpreted by this CLI. Inject catalogue storage, logger and runtime via the public embedding API when required.
- `--static-directory` explicitly enables SPA assets; no React/Vite dependency or default Chat build location. PID JSON contains `pid`, `port`, `cwd`; compatibility log filename is `pi-chat.log`. Shutdown via SIGINT/SIGTERM disposes listeners/runtimes and flushes CLI-owned logs. Embedders close their injected logger themselves.
- Restart re-executes compiled JS with a POSIX waiter; it does not build. Disable with `--no-restart` under external supervision. Chat's build-before-restart is not server policy.
- `npm run measure:server-memory` compares source-loader and compiled zero-session hosts in isolated agent directories, loopback ports and PID/log paths. Set `PI_SERVER_MEMORY_HOLD_MS` to control sample delay; supported on macOS/Linux. It never targets an existing backend.
- `npm run profile:session-open -- <project> [existing-session.jsonl]` is opt-in and uses real local Pi settings/extensions and history, without model prompts. It creates new sessions and performs scans; do not treat it as an isolated CI command. Timings are inclusive. Core migration tests and normal CI never invoke this diagnostic.
